# DardlashAI 2.3.0

Telegram-бот поддержки (ACT / РЭПТ). Языки: русский, узбекский, английский. Модель — **локальная через Ollama**, не облачный GPT-4.

Бот **не врач и не юрист**. Примеры про визу в промптах — не юридическая консультация.

## Что умеет

- Диалог поддержки: выговориться (VENTING) или разобрать проблему (SOLVING)
- Кризис: ключевые слова + классификатор, деэскалация, сообщение с живой помощью
- RAG по `knowledge_base.pdf` только в режиме SOLVING
- Голос: узбекский STT/TTS через Muxlisa; `/voice` включает озвучку ответов
- Живой аватар: Mini App с 3D-персонажем (TalkingHead), тот же диалог, что в чате
- Доступ по паролю из `.env`

## Команды в Telegram

| Команда | Что делает |
|---------|------------|
| `/start` | Начать заново, выбрать язык |
| `/language` | Сменить язык (если уже вошли — пароль не спрашивает) |
| `/voice` | Вкл/выкл голосовые ответы |
| `/help` | Справка и дисклеймер |
| `/avatar` | Открыть живой разговор с аватаром |

## Не путайте адреса

- **Ollama** — машина, где крутится модель (`OLLAMA_BASE_URL`, обычно `http://IP:11434`).
- **LOCAL_LLM_BASE_URL** — тот же Ollama, но путь `/v1` (OpenAI-совместимый API).
- **Telegram-бот** — этот репозиторий (`bot.py`). Токен только в `.env`.
- **Muxlisa** — отдельный сервис голоса, не Ollama.
- **Mini App / аватар** — HTTPS-страница (`MINIAPP_PUBLIC_URL`), которую открывает Telegram. Это не адрес Ollama и не webhook.

Если бот на Windows, а Ollama на Mac в той же сети — в `.env` пишите **IP Mac**, не `localhost`.

## Локальный запуск

1. Скопируйте `.env.example` в `.env` и заполните токен, пароль, адреса Ollama.
2. Проверьте, что Ollama отвечает: в браузере или `curl` откройте `http://IP:11434/api/tags`. Должен быть список моделей, среди них `qwen3:14b` и `nomic-embed-text`.
3. Создайте индекс знаний (нужен файл `knowledge_base.pdf` в папке проекта):
   ```powershell
   & ".\venv\Scripts\python.exe" ingest.py
   ```
   Готово, если появилась папка `faiss_index`.
4. Запустите бота:
   ```powershell
   & ".\venv\Scripts\python.exe" bot.py
   ```
   В логе должно быть `Ollama OK` и `polling` (или `webhook`, если задали `WEBHOOK_URL`).
5. В Telegram: `/start` → язык → пароль → напишите фразу.

## Живой аватар (Mini App)

Это не видеозвонок Telegram. Это страница внутри Telegram: лицо на экране, микрофон, тот же бот.

1. На сервере бот должен слушать порт **8090** (внутренний). В логе: `Mini App listening`.
2. В nginx добавьте кусок из `deploy/nginx-avatar.conf` (путь `/avatar/` → порт 8090).
3. В `.env` пропишите публичный адрес, который откроет Telegram, например `MINIAPP_PUBLIC_URL=https://your.domain/avatar/`
4. Перезапустите бота.
5. В Telegram: `/start` → язык → пароль → кнопка «Поговорить с аватаром» или `/avatar`.

Готово, если открывается лицо, строка «Можно говорить или написать», и ответ аватара совпадает по смыслу с ответом в чате.

Не открывайте в браузере `http://сервер:8090` как «сайт». Снаружи только HTTPS-домен.

Голос аватара: узбекский — Muxlisa (нужен токен); русский и английский — голос телефона. Для ru/en микрофон работает, если WebView умеет распознавать речь; иначе пишите текстом.

Если `BOT_ACCESS_PASSWORD` пустой, бот стартует **без пароля**. Это предупреждение в консоли, не ошибка.

## Оценка качества (P3)

1. Откройте `eval/rubric.md` — шкала 0–2 по эмпатии, языку, вреду, ACT, дисклеймеру.
2. Распечатайте 30 кейсов:
   ```powershell
   & ".\venv\Scripts\python.exe" eval\run_eval.py
   ```
3. Прогоните кейсы вручную в боте. Порог релиза: средний балл ≥ 1.5, на кризисных кейсах «вред» не должен быть 0.

Отдельную маленькую модель для кризиса не ставим: остаётся правило + та же `qwen3:14b`.

## Деплой на свой сервер

Не Render и не managed-хостинг. Два варианта.

### Docker

1. На сервере: папка проекта, файл `.env`, папка `faiss_index` (после `ingest.py`), пустая папка `data`.
2. Если нужен webhook — в `.env` укажите полный URL, который должен дергать Telegram, например `https://your.domain/telegram`. Если `WEBHOOK_URL` пустой — бот сам ходит в Telegram (polling).
3. Запуск:
   ```bash
   docker compose up -d --build
   ```
4. Проверка: `docker compose logs -f bot` — есть `Ollama OK` и нет падений. В Telegram `/help` отвечает.

### systemd

1. Скопируйте проект в `/opt/dardlashai`, поставьте venv и зависимости из `requirements.txt`.
2. Скопируйте `deploy/dardlashai.service` в `/etc/systemd/system/`.
3. `sudo systemctl daemon-reload` → `sudo systemctl enable --now dardlashai`.
4. Проверка: `sudo systemctl status dardlashai` — active (running).

Перед nginx: внутренний порт бота (по умолчанию 8080) не открывайте в браузере как «сайт». Снаружи — ваш HTTPS-домен, который проксирует на этот порт.

## Журнал пользователей

`ops.sqlite3` (или `OPS_DB_PATH`): таблица `users` (`last_seen`, язык) и `events` (кризисы). Это не переписка и не токены.

Сессии диалога по-прежнему в `bot_data.pkl` (pickle). Для продакшена смотрите папку `data/` в Docker.
